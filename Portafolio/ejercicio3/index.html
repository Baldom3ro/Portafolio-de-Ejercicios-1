Service Worker

Registro y ciclo de vida

Esta página demuestra cómo se registra un worker, cómo se precarga el app shell y cómo maneja la caché durante install, activate y fetch.

Evento

install

Precarga los recursos críticos y activa el worker con skipWaiting().

Evento

activate

Elimina cachés antiguas y toma control de la app mediante clients.claim().

Evento

fetch

Usa caché primero y, si falla la red, entrega una respuesta desde la caché.

Instrucciones de validación manual

  1. Abre esta página desde un servidor local con HTTP o HTTPS.
  2. En Chrome, accede a DevTools y abre la pestaña Application.
  3. Revisa la sección Service Workers para comprobar que el worker está activo.
  4. Ve a Cache Storage y verifica que se haya creado el caché del app shell.
  5. Activa Offline en la pestaña Network y recarga para comprobar la caché.

Paso 1: Instalación

Registro y Evento Install

El navegador registra el archivo sw.js asíncronamente desde app.js. Durante la instalación, el Service Worker ejecuta el evento install y almacena en caché el App Shell.

// Registro en app.js navigator.serviceWorker.register('./sw.js') .then(reg => console.log('Registrado:', reg.scope)); // En sw.js self.addEventListener('install', event => { event.waitUntil( caches.open('ejercicio3-cache-v1') .then(cache => cache.addAll(APP_SHELL)) ); });

Paso 2: Estados

Ciclo de Vida Completo

Un Service Worker pasa por diferentes fases independientes del hilo principal de la página.

1. Registrando

El navegador descarga y analiza el script sw.js.

2. Instalando

Ejecuta evento install y guarda archivos en caché.

3. En espera

Espera cierre de pestañas o skipWaiting().

4. Activando

Limpia versiones viejas de caché en activate.

5. Activo / Control

Intercepta peticiones fetch y controla la app.

Paso 3: Recuperación

Manejo de Estado Offline y Fetch

El evento fetch intercepta las solicitudes de red. Si el usuario pierde conexión, el Service Worker entrega la respuesta previamente guardada en la Cache API.
