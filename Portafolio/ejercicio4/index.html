Cache API

Estrategia Cache-First

Este ejercicio implementa almacenamiento en caché estática mediante la Cache API y la estrategia Cache-First, permitiendo que la aplicación cargue instantáneamente y funcione offline.

Paso 1

install

Abre el almacén ejercicio4-cache-v1 y precarga el App Shell crítico.

Paso 2

activate

Limpia versiones anteriores de caché y toma control inmediato de los clientes.

Paso 3

fetch (Cache-First)

Busca primero en caché; si no existe, consulta la red y almacena una copia.

Instrucciones de validación manual en DevTools

  1. Abre la aplicación en un servidor local (HTTP/HTTPS).
  2. Abre las DevTools y dirígete a la pestaña Application.
  3. Expande la sección Cache Storage para verificar el caché ejercicio4-cache-v1.
  4. Comprueba que todos los recursos estáticos estén precargados.
  5. Selecciona Offline en la pestaña Network y recarga la página para comprobar el funcionamiento offline.

Almacenamiento Estático

Precarga en Evento Install

Durante el evento install, el Service Worker abre la Cache API y descarga todos los recursos necesarios del App Shell para que estén disponibles de forma local.

const CACHE_NAME = 'ejercicio4-cache-v1'; self.addEventListener('install', (event) => { event.waitUntil( caches.open(CACHE_NAME).then((cache) => { return cache.addAll(APP_SHELL); }) ); });

Limpieza y Control

Evento Activate y Limpieza

El evento activate se encarga de purgar versiones antiguas de la caché para liberar espacio y evitar conflictos con recursos obsoletos.

1. Registro

El navegador registra sw.js.

2. Precarga

Guarda archivos en Cache Storage.

3. Salto

skipWaiting() activa el worker.

4. Purga

Elimina cachés viejas en activate.

5. Control

clients.claim() y Cache-First activo.

Estrategia de Intercepción

Cache-First en Evento Fetch

Cada petición HTTP pasa por el evento fetch. Con la estrategia Cache-First, la respuesta se sirve inmediatamente desde la caché si está disponible, reduciendo la latencia a cero.
